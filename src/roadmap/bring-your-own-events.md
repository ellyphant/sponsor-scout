Open source becomes more useful when the product can serve another community without absorbing its event platform. Let each independently operated desk choose an authorized source of sponsorship needs.

## What it looks like

- Start with CoHost Club or configure another documented read-only event feed; a dated file import can support research-only exploration.
- Preview the available events, actual asks, source identity, freshness and missing fields before starting a run.
- Choose the source for a run and keep its event set frozen with the resulting research.
- Reuse the same evidence review and human-approved outreach experience in a separately configured private instance.

## Key details

- Builds on safe open-source demonstration. This expands beyond the initial CoHost-only workflow; no extra event connector is a prerequisite for the initial build.
- Every source needs real event identity, an authoritative public link, upcoming dates, audience information and an explicit sponsorship need. Unknown facts stay unknown.
- Static imports remain research-only until there is a supported way to verify current event eligibility at dispatch. Uploading a file is not proof that its opportunities are still open.
- Keep source provenance and event identities distinct. Never silently mix failed live feeds with imports or samples.
- Each operator configures their own private access, credentials and sender. No hosted multi-tenant signup or shared contact pool is implied.
- CoHost remains a separate HTTP-only integration. Its source, database and authentication are not shared; no unsupplied write endpoint is assumed.

~~~
Require a documented, authorized source contract and an honest freshness policy before permitting live outreach for a new source. Preserve immutable snapshots, source isolation, Astra-only judgments and the initial dispatch safeguards.
~~~
